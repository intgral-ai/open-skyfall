# Input and decomposition through the conversation

The user supplies a description, image, or STL in the chat host. The Skill establishes units and evidence, preserves input, and proposes genuine physical parts. The STEP pane provides no source-upload or project-creation form.

## Verify the input path

1. Use the supported host import or actual HTTP/MCP input operation with an owned fixture. Record exact input bytes, source hash, explicit units, command, response, and entry point.
2. For the undimensioned PNG fixture, require `needs_evidence`, preserved input, no accepted CAD, and HTTP 409 for STEP retrieval. Open its viewer URL and require an evidence-waiting state with download disabled. Do not add a fabricated measured design to pass the refusal check.
3. Inspect a real STL with the CLI using declared units. Record measured bounds and errors. A refusal is a diagnostic, not a successful decomposition.
4. Use `get_reference_image` for the authorized image job in a connected host. Check that the agent distinguishes measured dimensions from inferred or hidden geometry.
5. Compare a proposed physical hierarchy with actual source evidence. Mesh connectivity alone does not establish physical part boundaries. A cover remains one part despite multiple construction stages.

The [project context journey](project-context-and-handoff.md) covers durable manual excerpts and requirements. Source acquisition, model planning, kernel construction, and viewer display have separate verdicts. A local API import does not establish an actual ChatGPT file-upload journey. Legacy upload limits and fitter restrictions remain unchanged.
