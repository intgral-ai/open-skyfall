# Image/text intake, physical review and native STEP delivery

Use the isolated candidate snapshot, owned service, browser session and evidence
directory from the [verification Skill](../SKILL.md). Record application commit
and candidate diff, authoring/verification Skill hashes, interpreter and native
binary identities, source/brief hashes and exact UI/HTTP/MCP actions. This is a
real workflow journey. Static fixture validation or passing transport tests do
not substitute for its browser, host, human-review or native stages.

## Independently author a proposal

Give a cold evaluator the [authoring Skill](../../../../skills/open-skyfall/SKILL.md),
an authorized fresh image or literal designed brief, and the owned service entry
point. Withhold the intended Plan, generator and example interpretation. Require
actual served image inspection or literal brief inspection, the live schema,
a proposed physical tree, uncertainties and proposed manufacturing notes.
Retain the evaluator's transcript and artifacts. Label unavailable independent
evaluation `BLOCKED`; do not relabel self-authored fixtures as cold authoring.

Create an image workflow through the real intake control with rights and a
description. Compare saved original bytes and source hash with the upload.
Confirm that initial state has source and brief, no fabricated geometry and no
native download. Submit the authored proposal through the documented host tool
path. Inspect its scheme, physical parts, unknowns and manufacturing proposals in
the pane before any geometry exists. Attempt Plan submission before approval
and require rejection without publication. Let the actual user explicitly
approve the displayed scheme, then require the persisted exact proposal digest.
Test proposal approval separately from physical-part confirmation.

Repeat intake with text only. Match stored `source.bin` bytes to the exact UTF-8
description and `workflow.brief.sha256`. Require the literal brief in the pane,
no fabricated reference image and no image-region observation. The evaluator's
text observations must quote literal brief text. Reject an absent quote and an
empty image/text intake without creating geometry. Verify an image-only project
also works without an invented textual source.

## Inspect the fine physical decomposition

Have the evaluator author and submit the source-bound v2 Plan after proposal
approval. Require one real physical tree, stable node/definition/shape IDs,
parent-relative poses, reusable identical definitions and full closed basis
coverage. Identify observed, estimated, assumed and unknown choices yourself.
Require genuine single-piece components, bore-bearing sleeves/collars, connected
screws, and explicit missing interface/tolerance information. Reject decorative
disconnected pieces masquerading as one physical part.

Open `show_decomposition` and the real returned project URL. Use tree and mesh
selection at whole, group and individual-part levels. Verify the selected label,
source basis, dimensional/pose evidence, definition reuse, manufacturing notes
and current trace against persisted Plan/program identities. Inspect at desktop
and phone widths. At 1x require a recognizable object; at 4x inspect contacts,
bores, fasteners and supporting faces, including the assembled and exploded
poses. Keep screenshots of the object and actual close-ups, not only cards.

Use isolation, hide, explosion and Restore with actual controls. Check depth
occlusion, clear silhouettes, selected accent and absence of leader-line clutter.
With reduced motion enabled, confirm motion stops or immediately settles.
Restore must produce exactly zero explosion offsets. Match saved assembled
poses before and after display-only operations. Native/download coordinates must
never contain exploded translations. Record any source/physical omission even
when the illustration looks convincing.

The labeled synthetic action has its own limited check. Open it through the
actual control and require `workflow.example_case = "inspection-rig"`, source,
literal brief and proposal, with no approvals, geometry or native build. Its
scheme contains 50 physical occurrences, six subassemblies, 26 definitions and
57 nodes. Only actual human proposal approval followed by `decompose-example`
may load that fixture's Plan. Confirm it is labeled an original proposed design,
with omitted interfaces and no recovered manufacturer BOM or factory claim.
Never use this fixture as independent authoring evidence for a fresh input.

## Capture and repeat an exact selected-part correction

Select one repeated physical occurrence. In the host conversation give a concrete
literal correction, for example `Make this bushing wall 2 mm; keep its bore and
all rail centers unchanged.` Retain the actual text, punctuation, selected node,
source/Plan/program binding, request ID and server-derived affected IDs. If the
UI sends a host message, retain actual host acceptance. If it falls back to copy,
require an honest clipboard-only label and inspect the copied text. A queued or
copied reference is not accepted host delivery or executed geometry.

Require the agent to read the immutable capture and current accepted state before
editing. It must explain that the shared definition affects all occurrences,
preserve unaffected IDs/poses and protected bore/rail dimensions, update the
design basis and proposed manufacturing notes, then submit the complete Plan
with both revisions and `request_id`. Compare the saved capture with the user's
exact original text. Verify an identical retry is idempotent and a changed text
under the same ID is refused. Inspect all affected occurrences in the pane.

Issue a second literal correction on the same node after the first accepted
revision. Require a separate immutable request and another real accepted change.
Show that camera and selection survive the update and that a stale Plan or
workflow revision is refused. Read a prior revision and replay its bundle into
an empty directory, retaining its original values. Replay checks remain separate
from native or source-fidelity checks.

## Explicitly confirm current review scopes

Before confirmation, compare `workflow.parts` and `workflow.scopes[node_id]`
with the pane's selected part IDs/count and review digest. Require the actual
user to review dimensions, evidence, interfaces and proposed manufacturing notes
and explicitly confirm that exact part or group. Observe the real confirmation
control and persisted `{node_id, review_digest, confirmed:true}` action. The
agent must never create test approvals as though a person supplied them.

Require a build attempt without current approval to fail, with native download
disabled. An unresolved captured request must prevent confirmation of its
affected scope. Check group confirmation binds every displayed member and
cannot cover parts outside the group. Selection, approved proposal, viewing a
preview and an earlier revision's confirmation must not imply current approval.

After a confirmed part, edit its geometry, pose, basis or manufacturing proposal.
Require affected approvals/native pointers and the complete assembly pointer to
invalidate. Repeated-definition changes must affect every linked occurrence.
Unchanged part confirmations may survive. Compare exact before/after digest
maps rather than assuming every label change invalidates every part. Historical
records and artifacts must stay immutable. Repeat confirmation only through a
new actual human review action.

## Build and inspect one native scope

Require the reviewed CPython 3.12 smlibpy runtime. Record its absolute path,
package identity, native binary and trusted runner/input hashes. If unavailable,
expect the visible unavailable/failure state and no fallback kernel. Label
actual native construction `BLOCKED`, even if refusal behavior passes.

Build a current confirmed physical part or subassembly through the real action.
Poll while it is running and require readable `workflow.status = "building"`.
Record that native/status metadata advances `workflow_revision` without changing
the concept revision. Inspect actual native stages and native report for unique
definition builds, one solid per definition, positive volume and validity. For
bored parts inspect their bores in the native preview. The concept triangle
count cannot establish a native solid.

Require per-definition STEP/SMB, native preview/report and placed-scope export
from the completed build. Check the chosen scope, current review binding and
artifact hashes. A partial result must not enable complete assembly download.
Toggle concept/native inspection and check labels/provenance, camera preservation,
correct picking and current native pointers. Workflow-only updates must repaint
status/downloads without rebuilding concept geometry or resetting the camera.

In a disposable project, use a disconnected multi-primitive definition and
require native refusal with retained diagnostics. During a real build, change
the relevant Plan/approval state through another authorized test action and
require stale output never to become the current native/download pointer.
Retain the failed/stale build evidence and verify the last eligible artifacts
remain correctly scoped. Never manufacture a success report to cover a refusal.

## Build and download the full assembled STEP

After actual human review confirms every current physical part, select the root
and build it. Require the current scope to cover all physical part IDs and only
then populate `workflow.cad.assembly`. In the synthetic case, require 50 named
placed bodies from 26 native definitions. Native assembly is the assembled pose,
regardless of the pane's current explosion slider.

Inspect `native-report.json` and `assembly.json`. Match source/brief, Plan,
review digests, runtime provenance, physical tree, occurrence names and full
parent-composed transforms. Require actual smlibpy STEP export and saved STEP
readback with healing disabled. Check exact body names/counts and measured
volume, bounds and placement against the native construction. Perform a
separate independent STEP structure parse or CAD import. Record omitted
interfaces and separate source-feature agreement checks.

Download through the current full-assembly button. Retain the actual binary,
HTTP build/artifact URL or embedded binary fallback transcript, filename, byte
count and SHA256. Match it to the current explicit build ID and artifact hash.
Test the embedded host path separately from a local browser anchor. Do not read
native files through the legacy concept registry or accept an old build as
current after a geometry change.

Require truthful delivery language. The current exporter produces flat named
BRep bodies. JSON carries the tree and transforms. Nested native STEP product
hierarchy, mates and transferred feature history must not be claimed. Editable
Plan/construction inputs, per-definition native artifacts, full STEP and bound
reports must actually exist before they are reported as delivered.

## Record separate verdicts

Report `PASS`, `FAIL`, `BLOCKED`, `NOT_RUN` or `NOT_APPLICABLE` for intake,
independent Skill authoring, proposal review, physical decomposition, repeated
literal iteration, actual host handoff, digest-bound human confirmation,
invalidation, native per-part construction, full assembly export/readback,
download identity, source fidelity and manufacturing. Give artifact paths and
concrete limits for each. Native validity and STEP exchange can pass while
source fidelity or production manufacturability remain unchecked. Proposed
material/process notes are never factory approval. A successful local run does
not establish ChatGPT-account delivery, calibrated operation or cost advantage.
